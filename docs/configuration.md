# Configuration

The repo uses native Helm values and Compose env files, plus a small number of
real files for multi-line configuration. Generated machine facts and runtime
keys stay out of the config tree.

For the end-to-end first install, start with
[`docs/runbooks/first-boot.md`](runbooks/first-boot.md). This page is the
reference for each configuration layer and default.

Before `init-config.sh`, set the target hostnames and run
`scripts/prereqs.sh` on each machine; `init-config` needs `yq` from prereqs.

## Layers

| Layer | Location | Who writes it |
|---|---|---|
| Universal automation secrets | `config/VARS.env` | you; copy `config_template/VARS.env` |
| srv0 Helm values | `config/srv0/values.yaml` | you; copy `targets/srv0/config_template/values.yaml` |
| srv0 Compose env | `config/srv0/compose.env` | you; public-exposure host/port |
| vps0 Compose env | `config/vps0/compose.env` | you; domains and app secrets |
| vps0 Authelia users | `config/vps0/authelia/users_database.yml` | you; copy the template |
| vps0 Authelia rules | `config/vps0/authelia/access_control.yml` | you; may be comments-only |
| Optional vps0 agent | `config/vps0/dscpln-agent/agent.json` | you; only when the Compose profile is enabled |
| Optional vps0 overlay | `targets/vps0/compose/compose.private.yaml` | you; only when needed |
| Machine facts | `targets/<t>/compose/.env` | generated by `prereqs.sh`/`compose.sh` |
| Public-exposure keys | `config/srv0/public-exposure/`, `config/vps0/public-exposure/` | `scripts/public-exposure-keygen.sh` |
| Remote-access profiles | `config/srv0/remote-access/` | `scripts/remote-access-client.sh` |
| Runtime state | `current_target/` | containers/scripts; never edit |

## Initialise

```bash
# On each machine first:
bash scripts/prereqs.sh

# Then, on the machine that owns the config:
bash scripts/init-config.sh srv0 --detect   # run on srv0
bash scripts/init-config.sh vps0            # run on vps0
```

`init-config.sh` copies templates without overwriting existing files. On srv0,
`--detect` also sets `MY_UID`, `GPU_PROFILE`, `HA_CONBEE`, and `HA_BLUETOOTH`
from the current hardware. It does not invent passwords or GitHub tokens.

Then fill:

- `config/VARS.env` for Renovate/CI (`RENOVATE_GITHUB_TOKEN`, `INFRA_REPO`,
  `APP_REPOS`; Docker Hub credentials are optional)
- `config/srv0/values.yaml` (domain, paths only where they differ from the
  defaults, app secrets, accelerator overrides)
- `config/srv0/compose.env` (`PUBLIC_EXPOSURE_HOST`, `PUBLIC_EXPOSURE_PORT`)
- `config/vps0/compose.env` (domains and app secrets)
- `config/vps0/authelia/users_database.yml`
- `config/vps0/authelia/access_control.yml`
- `config/vps0/dscpln-agent/agent.json` only if `COMPOSE_PROFILES` includes
  `dscpln-agent`

Authelia has two separate user sources: srv0 uses
`AUTHELIA_USERS_DATABASE` in `config/srv0/values.yaml`, while vps0 uses
`config/vps0/authelia/users_database.yml`. Keep the users and group names
consistent across both, and with the group names used by access rules and
Open WebUI/FileBrowser.

Run `bash scripts/validate.sh <target>`; it prints key names, not values, and
rejects placeholders in target config. `config/VARS.env` placeholders are
warnings because that file is only needed for Renovate/CI.

The reference stack is a personal catalog. If you do not use every app, remove
the unused templates/services and their `PUBLIC_HOSTS` labels; see
[Minimal stack](runbooks/first-boot.md#minimal-stack). `DSCPLN_AGENTS: {}` only
disables the archive agents, not the other D$CPLN apps or Task Runner.

## Path defaults

Only `MAIN_PARENT_DIR` and `SECONDARY_STORAGE_PATH` are required roots. Leave
the following empty to derive them:

| Key | Default |
|---|---|
| `INFRA_ROOT` | `<MAIN_PARENT_DIR>/Main/Infra` |
| `MEDIA_DIR_PATH` | `<MAIN_PARENT_DIR>/Main/Media` |
| `WA_TXT_PATH` | `<MAIN_PARENT_DIR>/Main/Backups/WhatsApp TXT` |
| `DSCPLN_LEDGER_PATH` | `<MAIN_PARENT_DIR>/Main/Documents/Balance` |
| `DSCPLN_CONFIG_PATH` | `<MAIN_PARENT_DIR>/Main/Code/Automation/dscpln-config` |
| `HOME_DIR` | `<MAIN_PARENT_DIR>` |
| `JOURNAL_DIR` | `/var/log/journal` |

## Accelerators and optional hardware

`GPU_PROFILE` (`intel|amd|none`) is the deployment-wide default. Per-app
overrides exist for mixed/fallback cases: `FRIGATE_DETECTOR`,
`FRIGATE_GPU_RESOURCE`, `IMMICH_ML_BACKEND`, `IMMICH_ML_GPU_RESOURCE`,
`JELLYFIN_HWACCEL`, `IMMICH_SERVER_HWACCEL`, `OLLAMA_GPU`.
`HA_CONBEE` and `HA_BLUETOOTH` remove the corresponding mounts/resources when
false. `init-config.sh srv0 --detect` sets all four initial values from the
current machine.

## Public hostnames

`PUBLIC_HOSTS` and `PRIVATE_HOSTS` in `config/srv0/values.yaml` are the exact
SAN labels appended to `SERVICES_DOMAIN`. Keep them aligned with the
HTTPRoutes; `validate.sh` reports route/SAN drift. Remove any public hostname
you do not serve before the first deploy, or Let's Encrypt HTTP-01 can fail for
a SAN with no DNS/route.

## Optional services

The vps0 D$CPLN archive agent is behind the `dscpln-agent` Compose profile.
Enable it with `COMPOSE_PROFILES=dscpln-agent` in `config/vps0/compose.env`;
leave the profile unset to skip it entirely.

## Standard commands

```bash
bash scripts/prereqs.sh                     # once per machine
bash scripts/init-config.sh srv0 --detect
bash scripts/validate.sh srv0
bash scripts/deploy.sh srv0                 # Helm + rollout checks
bash scripts/deploy.sh vps0                 # validate + render Authelia + compose
bash scripts/deploy.sh pc                   # validate + compose
bash scripts/compose.sh vps0 up -d           # direct Compose wrapper
bash scripts/compose.sh vps0 logs -f authelia
```

`deploy.sh` and `compose.sh` generate `targets/<t>/compose/.env`, add
`config/<t>/compose.env` and the private overlay when present, pass Compose
profiles, and render vps0 Authelia before `up`.

## Generated, do not hand-edit

- `targets/<t>/compose/.env`
- `config/srv0/public-exposure/*`, `config/vps0/public-exposure/*`
- `config/srv0/remote-access/*`
- `current_target/*`
- `current_target/compose_live_state/authelia/config/configuration.yml`

## Environment assumptions to review

- Tunnel/VPN ranges `10.99.0.0/24` and `10.100.0.0/24`, pod CIDR references
  `10.42.0.0/16`
- VPN DNS forwards to `127.0.0.53` (systemd-resolved)
- Traefik hostPorts `80`, `443`, `8443`
- Fedora/SELinux assumptions (`spc_t`, `s0`, host dbus)
- `opodsync` is amd64-only
- `hostpath-main` is a singleton
- `external-exposed` intentionally serves both the public edge and the LAN
  bridge/port-blocker
- Machine hostnames are expected to match target names (`srv0`, `vps0`, `pc`,
  `bigpc`, `rpi`) for host-level scripts and Compose.
