# Networking

- **Traefik on srv0** — Kubernetes Gateway API. Traefik runs as a pod-network DaemonSet (one pod per node) with `hostPort`s 80/443/8443 and **no Service**: no ServiceLB, no NodePorts, no kube-proxy LB VIPs, so the CNI hostPort DNAT is the only way in and it preserves real client sources (only pod/loopback hairpin traffic is masqueraded). The shared Gateway `srv0` in `base` (`templates/gateway.yaml`; GatewayClass `traefik` from the chart) exposes `web:80` (HTTP, plik only), `websecure:443` (LAN/VPN) and `websecure-proxy:8443` (PROXY protocol v2 from the public-exposure hub; trustedIPs are exactly `10.99.0.1/32`, the hub address every routed proxy flow is SNAT'd to). Public routes attach to both secure listeners; the private class (`files.$SERVICES_DOMAIN`, `traefik.$SERVICES_DOMAIN`, plus any future LAN+VPN-only app) attaches to `websecure` only, so the public-exposure tunnel can never reach it and LAN/VPN clients come in with real sources. TLS terminates on the listeners with two shared exact-name Certificates in `base` (`edge-certs.yaml`): `edge-public-tls` (the 25 public hosts) is attached to both secure listeners, and `edge-private-tls` (`files`, `traefik`) only to `websecure`, so the private names never reach the public-exposure listener. The names are exact, not a wildcard, but all public names share one key; adding a public app means adding its SAN and re-issuing. `validate.sh` checks every ref against a rendered Certificate; cross-namespace `HTTPRoute`→`Service` backends still use the `apps` ReferenceGrant. HTTPRoutes and Middlewares live in `base` (route files carry `namespace: base`) because Traefik resolves Middleware `ExtensionRef` filters only in the route's namespace; the chart's placeholder Gateway stays disabled (`gateway.enabled: false` in the HelmChartConfig), and the CRD + Ingress providers stay enabled (ExtensionRef filters; cert-manager's HTTP-01 solver). Available middlewares: `geoblock` (allowlist plugin using the public `get.geojs.io` API; `apiTimeoutMs=2000`, LRU cache 1000; fails closed if the API is unreachable), `crowdsec-bouncer` (stream mode + AppSec on `:7422`), `forwardauth-authelia`, `jellyfin-ratelimit`, `local-no-store`, `win-header-auth` (pins Guacamole's header identity to `shared` after Authelia). HTTP → HTTPS redirect; readTimeout=0 on both secure entrypoints (streaming). Plugin versions are pinned in `additionalArguments` and regex-managed through `github-releases`. The `allow-traefik-ingress` policy in kube-system admits non-pod sources by ipBlock — the public-exposure hub (`10.99.0.1/32`, ports 80/8443) and remote-access clients (`10.100.0.0/24`, ports 80/443) — because kube-router rejects anything else with ICMP port-unreachable.
- **App auth routes** — services with their own authentication (Home Assistant, Immich, Jellyfin, Linkwarden, Navidrome, Opodsync) have **no Authelia forward-auth filter**; their host route keeps crowdsec/ratelimit (Jellyfin also has `jellyfin-ratelimit`). `BOOTSTRAP_PRIVATE_APPS: "true"` temporarily removes the `websecure-proxy` parentRef from those six routes so they remain LAN/VPN-only until Authelia is Ready. The custom header-gate WASM plugin is gone.
- **Out-of-cluster backends (pattern)** — Traefik can route to any address reachable from its pods, not just pod-backed Services: a Service with no selector plus a hand-written EndpointSlice whose `kubernetes.io/service-name` label names that Service. Traefik's Gateway provider reads EndpointSlices directly (matching the backend port by the Service port's name) and treats a missing `ready` condition as not-ready, so each endpoint needs an explicit `conditions: {ready: true, serving: true}`. Binding a host process to the node's flannel bridge (e.g. `10.42.0.1:4096`) makes it cluster-reachable but invisible to the LAN and the public-exposure tunnel; the HTTPRoute/Certificate/middleware setup is identical to any other app. Minimal shape:

  ```yaml
  apiVersion: v1
  kind: Service
  metadata: {name: hostapp, namespace: base}
  spec:
    ports: [{name: http, port: 4096, targetPort: 4096}]
  ---
  apiVersion: discovery.k8s.io/v1
  kind: EndpointSlice
  metadata:
    name: hostapp
    namespace: base
    labels: {kubernetes.io/service-name: hostapp}
  addressType: IPv4
  ports: [{name: http, port: 4096}]
  endpoints:
    - addresses: ["10.42.0.1"]
      conditions: {ready: true, serving: true}
  ```
- **vps0 edge** — one Traefik routes by Host/SNI: local services via Docker labels (two zones, see `docs/architecture.md`); `home.$SERVICES_DOMAIN` + wildcard goes through the file provider (the `traefik_dynamic` compose config) to `10.99.0.2:80` (HTTP) / `10.99.0.2:8443` with `tls.passthrough` + PROXY protocol v2 — vps0 never terminates srv0's TLS; cert-manager on srv0 owns the LE lifecycle. cert-manager on srv0 additionally maintains a local chain (self-signed → `k3s-local-ca` → `ca-issuer`) for MQTT TLS. `plausible.$SERVICES_DOMAIN` is Cloudflare-proxied with Bot Fight Mode on the `imranr.dev` zone (CF config lives in the external `imranr.dev-cloudflare-terraform` repo, applied with OpenTofu): Traefik trusts the CF edge ranges in `forwardedHeaders` (and the crowdsec plugin's `forwardedHeadersTrustedIPs`) so logs/CrowdSec see real client IPs, and the `obtainium_apps` SSR stats fetch bypasses Cloudflare (`extra_hosts` → host gateway) because Bot Fight Mode cannot be skipped on the Free plan.
- **Public-exposure tunnel (WireGuard)** — `public-exposure-server-wg` on vps0 (host network, NET_ADMIN, linuxserver/wireguard image) creates `pubexp-server0` (10.99.0.1/32, ListenPort 51822/udp) and maps the public ports to tunnel addresses via kernel DNAT from `files/public-exposure/forwards.conf`: 8887/tcp preboot, 56881 tcp+udp qBittorrent, 51820/udp the AmneziaWG endpoint (srv0's listener stays 51830 — flannel owns 51820; the 8888 SSH tunnel is gone, the jump host dials `10.99.0.2:22` directly). A `masq` flag SNATs flows whose target would otherwise reply via its own default route (preboot, AmneziaWG), while qBittorrent keeps real peer source IPs. The MTU is 1340 because the srv0↔vps0 path is 1420, and both sides clamp TCP MSS; all host effects are applied on container start and removed via a SIGTERM trap. `public-exposure-client-wg` on srv0 (compose sidecar) owns `pubexp-client0` (10.99.0.2/32); `public-exposure-watch` prints preboot handshakes for logtfy.
- **Remote SSH** — srv0's sshd still listens on the LAN; non-LAN SSH jumps through vps0's sshd, which connects to `10.99.0.2:22` over the public-exposure tunnel. vps0 logs (and logtfy reports) the real client IP, srv0 sees `10.99.0.1`. Client config:

  ```
  Host srv0
      HostName 10.99.0.2
      User imranr
      ProxyJump root@vps0.imranr.dev
      HostKeyAlias srv0
  ```
- **WireGuard** (`wireguard.sh`, machine-local) — deploys a provider `wg0.conf`. It parses the provider conf (PrivateKey/Address/DNS/MTU/PresharedKey/Endpoint — values never echoed), rewrites `AllowedIPs` to `0.0.0.0/1, 128.0.0.0/1` (split tunnel: less specific than LAN routes, so K3s subnets and LAN stay direct), and adds PostUp/PreDown `/32` routes for the endpoint via the physical gateway (dead-loop fix). Installs `wireguard-tools`, writes the 0600 `/etc/wireguard/wg0.conf`, and enables `wg-quick@wg0` (config changes apply via `wg syncconf`).
- **AmneziaWG VPN server** (`targets/srv0/k3s-base/templates/vpn.yaml`) — a hostNetwork pod pinned by `nodeSelector: infra.local/external-exposed` (the static NFS/public-exposure node label) so it stays on the node with the tunnel; it runs the userspace `amneziawg-go` implementation (official image, no host kernel module; `/dev/net/tun` mounted) and creates `ra-amneziawg0` (10.100.0.1/24, ListenPort 51830 — flannel-wireguard owns 51820) in the host netns, masquerading full-tunnel client traffic (0.0.0.0/0) via iptables. The hub DNATs `vps0:51820/udp` to `10.99.0.2:51830` over the tunnel (masq'd so the server's replies return through it). The companion `remote-access-dns` pod binds CoreDNS to 10.100.0.1:53 only (unreachable from LAN/public) and answers every `*.$SERVICES_DOMAIN` name with 10.100.0.1, forwarding everything else to `127.0.0.53` (systemd-resolved's stub on the node; the pod is hostNetwork, so the host's live resolver config applies). Keys and one AWG 3 obfuscation set (Jc/Jmin/Jmax, S1-S4, H1-H4, HeaderProtectionKey, ContentPaddingAddition, client-side I1-I5) are generated on first start by the pod's `keygen` init container and persisted on the `remote-access-amneziawg-pvc` (`auto-backup: "true"`), with `REMOTE_ACCESS_AMNEZIAWG_ENDPOINT`/`_CLIENTS` as committed chart values; profiles are fetched with `scripts/remote-access-client.sh <client>` and use `DNS = 10.100.0.1`, `MTU = 1180`, `PersistentKeepalive = 25` — only AmneziaWG-capable clients can connect (vanilla WireGuard apps cannot). The `conn-notify` sidecar watches handshakes over the shared UAPI socket and publishes `<client> connected.` to ntfy topic `srv0_services_vpn` (admitted by `allow-notification-ingress`). To regenerate, delete `/wg/ra-amneziawg0.conf` (or the PVC) and restart the pod — existing client profiles then stop working. `k3s-node-prep.sh` trusts `10.100.0.0/24` like the pod CIDRs: ra-amneziawg0 appears at runtime, so firewalld never binds it to a zone and the default zone would reject the clients' DNS and forwarded traffic. The pod's start script also installs host-netns iptables FORWARD accepts for the subnet (Docker leaves FORWARD `DROP` and kube-router only accepts pod traffic) and a POSTROUTING exception (`RETURN` for `10.42.0.0/16`/`10.43.0.0/16`) ahead of its masquerade rule, so cluster-destined traffic keeps the real `10.100.0.x` source (policies and Traefik see the true client) instead of the node's pod-gateway address; LAN/WAN traffic is still masqueraded so replies come back through the tunnel.
- **LUKS preboot** (`preboot.sh <public-exposure|crypt-ssh>`, on the node) — srv0 (public-exposure): reads `pre0.key`/`server.pub` from `config/srv0/public-exposure/` and `PUBLIC_EXPOSURE_HOST`/`PUBLIC_EXPOSURE_PORT` from `config/srv0/compose.env`, resolves the hub IP itself (`getent hosts`), builds a wg-native conf, and installs the `99pubexp` dracut module (from `ImranR98/dracut-remote-luks-unlock`; `PREBOOT_REPO`/`PREBOOT_REF` override the source for testing) which brings up `pubexp-pre0` in the initramfs; the hub DNATs `8887/tcp` to `10.99.0.4:22`. bigpc (crypt-ssh): dropbear patched to `preboot_port` for direct LAN unlock (ethernet only). Re-run on srv0 after rotating the preboot key. When adding initramfs networking, verify with `lsinitrd` that the module, `wg`/`ip` and firmware actually made it in — drivers don't retry firmware loads after pivot_root.
- **Static node labels** — `infra.local/hostpath-main=true` and `infra.local/external-exposed=true` are set by `k3s-server.sh` on the server; `k3s-join.sh --hostpath-main` sets the first on a joined node. NFD/node-facts are gone; `validate.sh` warns if srv0 is missing either label.
